# 19.6단계 화면 가독성 및 결과 테이블 개선

최종 판정: **A — 확인한 화면 크기에서 제목·설명·차트 겹침 해소, 사용자 중심 표와 핵심 결과 보존 확인**.

## 수정 전후

| 구분 | 수정 전 | 수정 후 |
|---|---|---|
| 행별 결과 | 128개 특징이 예측 결과보다 먼저 표시됨 | 측정 번호·AI 예측 가스가 먼저 보이는 한글 요약 표 |
| 정답 | 긴 원본 표에서 확인 | gas 제공 시에만 실제 가스·일치/불일치 표시 |
| 원본 특징 | 선택 행과 전체 원본 표가 연속 노출됨 | 접힌 원본 영역에서 선택 행/전체 행을 전환하는 표 하나 |
| 선택 행 | 선택한 원본 행 표 | 측정 번호·예측 가스·선택적 실제 가스를 간단히 안내 |
| 패턴 결과 | window·score·SHA 등 영문 필드 노출 | 분석 구간·측정 범위·패턴 차이 점수·결과 우선 표시 |
| 차트 | 긴 내장 제목과 축 이름 | 제목을 차트 밖으로 분리하고 축 이름을 단축함 |
| 긴 가스 이름 | 한 줄 한영 이름 | 한글/영문 두 줄 라벨 사용 |
| 좁은 화면 | 상단 제목 가림과 표 해석 어려움 | 상단 여백 확보, 반응형 차트, 고정 번호 열과 표 내부 스크롤 |

기존 UI 사본: `outputs/streamlit_ui_readability/ui_before.py.snapshot`.
이전 단계 화면: `outputs/streamlit_ux/desktop_result.png`.

## 결과 표

한 행이 하나의 센서 측정 샘플임을 안내함. 특징 128개는 가스 128종을 뜻하지 않음을 원본 영역에 표시함. 기본 예측 표에는 원본 특징·모델 지문이 섞이지 않음.

정답이 없는 입력은 측정 번호·AI 예측 가스만 표시하고 ‘정답 미제공’을 안내함. 정답이 없는 상태에서 실제 가스나 일치 여부를 만들지 않음. 정답 기반 Accuracy/Macro F1도 표시하지 않음. 기존 평가 계산 정책은 그대로 유지함.

원본 표에는 측정 번호와 f001~f128 전부를 원래 순서로 유지함. 선택한 측정값 또는 전체 측정값을 전환하여 확인할 수 있음. 측정 번호를 고정 열로 두고, 나머지는 표 내부에서 가로 이동함. 실제 브라우저에서 f120~f128까지 이동하여 마지막 특징 접근을 확인함.

패턴 표의 결과는 저장 감지기의 status/alert를 사용함. 화면에 표시한 반올림 점수로 경고를 다시 계산하지 않음. 점수는 화면에서 소수 6자리로 표시하지만 내부 값과 다운로드 원본 정밀도는 유지함. 평가 불가 구간은 ‘평가 불가’이며 정상 구간으로 표시하지 않음. 기술 정보에는 원본 창별 결과·reason·threshold·버전·SHA 등을 유지함. 100행 미만일 때 의미 없는 빈 표 대신 사유를 안내함.

## 차트와 반응형 화면

Streamlit `width="stretch"`와 Altair의 컨테이너 너비를 사용함. 차트 고정 폭, 데이터를 숨기는 overflow 규칙은 추가하지 않음. 제목과 설명을 독립 Streamlit 요소로 표시하여 차트 내부 제목과 겹치지 않게 함. 패턴 축을 ‘분석 구간’, ‘패턴 차이 점수’로 단축하고 실제 지표 RFF-MMD²와 고정 기준은 아래 설명에서 제공함. 혼동 행렬도 짧은 외부 제목과 한글 가스 라벨을 사용함.

데스크톱 1280px, 태블릿 768px, 모바일 390px에서 실제 앱 내 브라우저로 점검함. 확인한 크기에서 제목·설명·차트 축의 겹침은 관찰되지 않았음. 넓은 표의 모든 열을 한 화면에 축소해 넣지는 않음. 태블릿·모바일에서는 일부 열이 처음부터 동시에 보이지 않지만 내부 가로 스크롤로 접근 가능함. 모바일에서 번호 열을 고정한 채 패턴 점수와 경고 결과로 이동하는 것을 확인함.

## 기능 유지 및 출력 동일성

- 공식 분류·감지 서비스 및 저장 모델 수정 없음. 재학습·튜닝·자동 모델 교체 없음.
- 창 100행, 고정 임계값 `0.00825701197565701` 유지함.
- 99/100/101/200행 × 정답 유무의 8조건에서 기존 19.5단계 CSV 3종 SHA-256 기준과 바이트 동일성 검사를 통과함.
- 한글 표의 측정 번호·예측 가스·실제 가스·일치 여부가 원본 결과와 행별로 대응함을 검사함.
- 표 생성 전후 rows/windows/counts 및 다운로드 바이트가 변경되지 않음을 검사함.
- 부분 결측으로 인한 평가 불가 창, 열 재정렬, 잘못된 입력, 파일 변경·제거 시 상태 초기화와 기존 Batch 7 예측 재현 검사도 유지함.
- 기존 원본 Batch 9~10 읽기는 검사 훅으로 차단함. 신규 성능 평가를 하지 않음. 합성 CSV는 기능 검증용이며 연구 성능으로 해석하지 않음.

## 테스트

대상 테스트 **55개 통과**: 기존 웹앱 34개, 19.5단계 10개, 신규 가독성 11개. 기존 테스트 파일은 수정하지 않음.

전체 테스트는 보존·접근 제한 훅을 적용하여 실행함. 최종 전체 결과와 기존 실패의 상세 원인은 아래 최종 실행 기록에 기재함. 건너뜀은 통과로 간주하지 않으며 제한 없는 전체 테스트 통과를 주장하지 않음.

신규 테스트 최초 실행의 2건 실패는 원본 표시 범위 대신 화면 메뉴 radio를 위치로 선택한 테스트 코드 문제였음. 라벨로 정확한 위젯을 선택하도록 수정 후 11개 모두 통과함. 이후 전체 재확인 중 pytest 메모리 부족으로 실행이 중단된 기록은 `resource_attempt.txt/xml`에 별도로 보관함. 모델 결과를 바꾸어 테스트를 통과시키지 않음.

재실행 명령:

```powershell
.\.venv\Scripts\python.exe -B -m pytest tests -q --tb=line -p src.webapp.readability_testing_guard -p no:cacheprovider
```

## 브라우저 기록 및 남은 한계

실제 합성 정답 CSV 업로드 → 분석 → 상세 결과 표 → 원본 특징 펼침 → f128 접근 → 패턴 표 가로 이동을 확인함. 초기의 기존 세션에서 HTTP 400 업로드 오류가 있었으며 새 세션에서는 같은 파일 업로드가 정상 완료됨. 입력 검증이나 보안 설정을 완화하지 않음.

정답 유무·측정 번호 변경·전체 원본 표시·99/100/101/200행 경계는 실제 Streamlit 위젯 기반 AppTest에서도 확인함. 모든 입력 조합을 실제 브라우저에서 각각 반복한 것은 아님.

CSV 다운로드 버튼 3종과 기존 파일명·내용·정렬은 유지함. 일반 브라우저의 다운로드 폴더 저장 완료는 여전히 미확인임. 사용자 지시대로 이 항목을 UI 가독성 판정과 구분함. 다양한 기기·브라우저·접근성 도구나 실제 사용자 이해도 조사는 수행하지 않음.

화면 캡처는 `outputs/streamlit_ui_readability/screenshots/`에 있음. 초기 점검 캡처와 `final` 캡처를 이름으로 구분함. 캡처의 가스 예측·패턴 점수는 합성 입력에 대한 기능 점검 수치임.

## 파일 및 실행

수정: `src/webapp/ui.py`만.

신규:

- `src/webapp/readability_audit.py`: 기존 파일 읽기 전용 해시 검사.
- `src/webapp/readability_testing_guard.py`: 원본 9~10 읽기·과거 보호 파일 쓰기 차단.
- `tests/test_streamlit_readability.py`: 한글 표·원본 128열·행 정렬·출력 불변·원본 표시 전환 검사.
- 본 보고서와 `outputs/streamlit_ui_readability/` 내 계획·사전/사후 보존 기록·테스트 로그·캡처.

실행 방법은 기존 `README_streamlit.md`와 동일함:

```powershell
.\.venv\Scripts\python.exe -B -m streamlit run app_streamlit.py --server.address 127.0.0.1 --server.port 8501 --server.headless true --browser.gatherUsageStats false
```

Git Commit·Push 수행 없음. 원본 데이터·기존 18~19.5단계 보고서·모델·해시 기록 수정 없음. 반자동 재학습 기능은 구현하지 않음.

## 최종 실행 기록

- 전체: **197개 통과, 기존 실패 2개, 제한에 따른 건너뜀 90개**. 신규 코드 실패 없음.
- 기존 실패: 과거 임시 파일 `outputs/model_comparison/zNex~$haremetrics.csv` 부재, 과거 고정 모델 목록과 후속 단계 추가 모델 목록 충돌.
- OpenBLAS 자원 부족이 발생한 재시도는 `resource_retry.txt/xml`에 보존함. 해당 실행은 196개 통과·기존 실패 2개·자원 실패 1개·건너뜀 90개였음. 최초 메모리 중단과 구분함.
- 최종 전체 실행은 테스트 프로세스에서만 OPENBLAS_NUM_THREADS/OMP_NUM_THREADS/MKL_NUM_THREADS=1을 적용함. 코드·모델 설정을 바꾸지 않았으며, 이 조건에서도 8개 입력 조건의 과거 CSV 해시 동등성 검사가 통과함.
- 보존: UI 외 기존 파일 **1465개** 해시 일치, 모델 **325개** 유지. 과거 보고서·테스트·모델·기존 해시 기록 변경 없음.
- 원본 데이터 쓰기는 수행하지 않았으며, Batch 9~10을 새로 열어 전체 원본 해시를 다시 계산한 것은 아님.
